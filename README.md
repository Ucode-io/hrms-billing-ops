# hrms-billing-ops — кабинет оператора биллинга HRMS

Интерфейс для сотрудника Udevs, который ведёт биллинг HRMS: назначает планы компаниям,
отмечает банковские платежи, правит каталог тарифов и печатает счета.

Своего бэкенда нет. Всё считает Knative-функция **`udevs-hrms-billing`** (репозиторий
`ucode/knative/udevs-hrms-billing`), сюда приходят только готовые цифры.

- Прод: https://billing.ucode.co
- Вход: тот же логин и пароль, что и в HRMS (hrms.ucode.co)
- Доступ: глобальная роль `billing_operator`. Её проверяет **сервер** на каждом методе —
  экран «Нет доступа» лишь объясняет отказ.

## Что умеет

| Страница | Что делает |
|---|---|
| **Компании** | Список всех компаний HRMS: статус подписки, план, сотрудники, баланс, долг, дата следующего списания. Поиск, фильтр по статусу, итоги сверху. Кнопка «Пересчитать сейчас» — ручной запуск того же цикла, который функция выполняет сама каждые 15 минут. |
| **Карточка компании** | Подписка и даты, счета (печать, аннулирование), движения по балансу, сотрудники по дням текущего периода, карты и попытки автосписания, история событий. Действия: назначить план / снять с биллинга / отменить, отметить платёж, корректировка баланса, начислить AI-токены, ручная правка дат, пересчёт по одной компании. |
| **Планы и пакеты** | Каталог тарифов и пакетов AI-токенов — создание и правка прямо здесь, без деплоя. Кнопка пересчёта лимитов токенов по формуле из настроек. |
| **Настройки** | Реквизиты Udevs для счетов, число платных дней отсрочки, параметры расчёта AI-лимитов, цены моделей. |
| **Печать счёта** | `/invoices/:id/print` — счёт на оплату с реквизитами на дату выпуска, суммой прописью и курсом ЦБ. Открывается в новой вкладке, печатается без меню. |

Денежные действия идемпотентны: каждая мутация уходит с `request_id`, повторный клик или
ретрай не спишет и не зачислит второй раз (сервер ответит `duplicate`).

## Разработка

```bash
npm install
npm run dev        # http://localhost:5200
npm run lint       # tsc --noEmit
npm run build      # tsc -b && vite build
```

Адреса шлюза и функции зашиты в `src/api/gateway.ts`, параметры входа — в `src/api/auth.ts`
(они те же, что в hrms-admin). API-ключ используется **только** формой входа; все данные
идут с Bearer вошедшего человека, поэтому увидеть чужое через ключ нельзя.

## Структура

```
src/
  api/        gateway.ts (invoke метода), auth.ts (вход), billing.ts (типы + react-query)
  components/ ui.tsx (кнопки, таблицы, модалки, тосты), Layout.tsx
  lib/        format.ts (деньги, даты, словари статусов), words.ts (сумма прописью)
  pages/      Tenants, Tenant, Plans, Settings, Login, InvoicePrint
  store/      auth.ts (токен в localStorage)
```

## Деплой

GitHub Actions (`.github/workflows/ci-cd.yaml`) → образ в ghcr.io → ArgoCD по
`Ucode-io/deployments`. Статика, nginx, Vault не используется (переменных окружения нет).

Нужно со стороны devops:
1. Репозиторий `Ucode-io/hrms-billing-ops` (приватный) и доступ у workflow `Ucode-io/ci-cd`.
2. Папка сервиса в `Ucode-io/deployments` с `k8s/values.yaml` и `k8s/config.json` из этого репо.
3. A-запись `billing.ucode.co` на ingress прода `162.55.157.151` — у `ucode.co` нет wildcard,
   сертификат выпустит cert-manager по явному блоку `tls` в values.
